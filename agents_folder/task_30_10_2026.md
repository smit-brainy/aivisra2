## 4. Final Auth Schema (confirmed 2026-10-30)

Location: a single SQLite file at **`backend/database.db`**. The path is
resolved from `backend/database.py` via `Path(__file__)`, so it works no matter
where the repository lives. Every application table (`areas`, `camera_metadata`,
`app_settings`, `users`, `sessions`) lives in that file.

Override for tests/deployments with `STREAMCORE_DB` (legacy `STREAMCORE_STATE_DB`
is still honoured). The file is gitignored.

`track_events` still lives in `runtime/streamcore/output/events.db`; moving it
into `database.db` is deferred to a later phase.

### 4.1 `users`

```sql
CREATE TABLE IF NOT EXISTS users (
    user_id       TEXT PRIMARY KEY,                  -- uuid4 hex
    username      TEXT NOT NULL,                     -- login id
    display_name  TEXT NOT NULL DEFAULT '',
    password_hash TEXT NOT NULL,                     -- scrypt$N$r$p$<salt_b64>$<hash_b64>
    role          TEXT NOT NULL DEFAULT 'operator'
                  CHECK (role IN ('admin','operator','viewer')),
    is_active     INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0,1)),
    last_login_at REAL,
    created_at    REAL NOT NULL,
    updated_at    REAL NOT NULL
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_users_username
    ON users (username COLLATE NOCASE);
```

Confirmed decisions:
- Roles are exactly `admin` / `operator` / `viewer`.
- Password policy: **any** password is accepted (common passwords allowed);
  only `3 <= len(password) <= 15` is enforced.
- No lockout: `failed_attempts` / `locked_until` are **not** in the schema.
- No `must_change_password`; there is no forced-change flow.
- `last_login_at` is kept and stamped on successful sign-in.

### 4.2 `sessions` (opaque server-side sessions)

```sql
CREATE TABLE IF NOT EXISTS sessions (
    session_id   TEXT PRIMARY KEY,                  -- sha256 of the opaque token
    user_id      TEXT NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
    created_at   REAL NOT NULL,
    expires_at   REAL NOT NULL,
    last_seen_at REAL NOT NULL,
    ip           TEXT,
    user_agent   TEXT,
    revoked      INTEGER NOT NULL DEFAULT 0 CHECK (revoked IN (0,1))
);

CREATE INDEX IF NOT EXISTS idx_sessions_user   ON sessions (user_id);
CREATE INDEX IF NOT EXISTS idx_sessions_expiry ON sessions (expires_at);
```

Confirmed decisions:
- No idle timeout and no absolute timeout. `expires_at` stays `NOT NULL` and is
  filled with `backend.database.NO_EXPIRY` (`4102444800`, 2100-01-01).
- `last_seen_at` is updated on each resolve for observability only; it is never
  used to reject a session.
- Logout revokes the row (`revoked = 1`); revoked sessions resolve to `None`.

### 4.3 `audit_log` (in scope)

```sql
CREATE TABLE IF NOT EXISTS audit_log (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id    TEXT,                                -- no FK: entries survive deletes
    action     TEXT NOT NULL,                       -- e.g. auth.login.failed
    resource   TEXT,                                -- e.g. cameras/CAM001
    detail     TEXT,                                -- JSON string or free text
    ip         TEXT,
    created_at REAL NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_audit_time ON audit_log (created_at);
```

Written through `backend/auth/audit.py` (`AuditLog.record/list_entries/count_entries`).
Actions use dotted names (`auth.login`, `auth.logout`, `user.create`,
`user.update`, `user.delete`, `camera.update`, `area.create`, ...). Callers
record at the API layer so a failed audit write cannot silently bypass a
business rule.

### 4.4 Decisions recorded

| # | Question | Decision |
| --- | --- | --- |
| 1 | Roles | `admin` / `operator` / `viewer` |
| 2 | Password policy | Any password; `3 <= len <= 15` |
| 3 | Lockout | None |
| 4 | Session lifetime | No idle/absolute timeout; keep `last_login_at` |
| 5 | First admin | First-run setup screen (no env bootstrap) |
| 6 | `audit_log` in scope now | Yes — table + helper included |
| 7 | DB location | Single `backend/database.db` for all tables |

First-run flow: while `UserStore.has_any_users()` is `False`, the UI shows a
"create the first administrator" form. It posts to `POST /api/auth/setup`
(Phase 2), which calls `UserStore.create_first_admin()` — a single
`BEGIN IMMEDIATE` transaction that refuses to run once any user exists.

## 5. Proposed RBAC Model

Permissions are `resource:action` strings. Roles map to permission sets in one
module (`backend/auth/permissions.py`) so the matrix is easy to change.

| Permission | admin | operator | viewer |
| --- | :---: | :---: | :---: |
| `cameras:read` | yes | yes | yes |
| `cameras:write` | yes | yes | no |
| `areas:read` | yes | yes | yes |
| `areas:write` | yes | yes | no |
| `live:view` | yes | yes | yes |
| `events:read` | yes | yes | yes |
| `clips:read` | yes | yes | yes |
| `snapshots:read` | yes | yes | yes |
| `spatial:read` | yes | yes | yes |
| `spatial:write` | yes | yes | no |
| `onboarding:run` | yes | yes | no |
| `settings:read` | yes | yes | yes |
| `settings:write` | yes | no | no |
| `users:manage` | yes | no | no |
| `audit:read` | yes | no | no |

Enforcement:
- Backend: FastAPI dependency `require_permission("cameras:write")` attached per
  route; a global dependency resolves the session cookie to a `UserContext`.
- Frontend: `AuthContext` exposes `can(permission)`; nav items and action
  buttons are hidden/disabled accordingly. The backend remains the source of
  truth.
- Transport: `HttpOnly`, `SameSite=Lax` session cookie. Vite already proxies
  `/api` to `127.0.0.1:8765`, so dev is same-origin.
