# AIVISRA StreamCore — Local VLM & Search Migration: Work Done Report

## 1. Executive Summary & Objective

The objective of this migration was to transition **AIVISRA StreamCore** from a cloud-dependent Google Gemini architecture to a **100% fully local, offline AI surveillance system** operating entirely on the host GPU (NVIDIA GeForce RTX 5070) with **zero cloud API calls** and **zero external network dependencies**.

The system now operates with:
- **Object Detection**: Batched YOLO11 FP16 across all 80 COCO classes (`[0..79]`).
- **Motion & Tracking**: ByteTrack validating trajectory, hits, and track confirmation.
- **Local VLM**: `qwen3.5:9b` via local Ollama server (`http://127.0.0.1:11434`) generating surveillance descriptions and visual keywords from 10% padded bounding-box crops.
- **Local Text Embedder**: `embeddinggemma-2:740m` via local Ollama generating 768-dimensional normalized vectors.
- **Vector Storage**: FAISS (`IndexFlatIP`, dim=768) storing normalized embeddings for instant cosine similarity retrieval.
- **Database & Metadata**: SQLite (`events.db`) storing full detection records, VLM descriptions, video clip paths, and a strict 1:1 `vector_id_map` table linking FAISS row positions to event IDs.
- **Natural Language Temporal Query Engine**: A modular, class-based `TimeAndQueryResolver` resolving vague human queries, relative days, clock ranges, and camera validation.
- **Web UI & Streaming**: HTTP 206 Range video streaming for 10-second MP4 clips, instant snapshot previews, and a modernized local VLM status badge.

## 3. Detailed Work Completed

### 3.1. Zero Gemini Policy & Cloud Decoupling
- **`runtime/streamcore/events/visual_search_manager.py`**:
  - Completely removed the `EmbeddingService` dependency.
  - Eliminated all Google Gemini API references, keys, and cloud endpoints.
  - Routed all embedding and intent parsing directly to local models.
  - Implemented 100% offline fallback: if Ollama is busy or offline, the system automatically falls back to local OpenCV color-band analysis and deterministic 768-dim semantic projection (`_deterministic_text_embed`).
- **`runtime/streamcore/events/embedding_service.py`**:
  - Updated key resolution to immediately abort and stay dormant when `disabled` or `local` mode is active.
- **`runtime/streamcore/config.py`**:
  - Removed `gemini_api_key` requirement.
  - Set `search_backend: local` as default.
- **`runtime/streamcore/app.yaml`**:
  - Configured `search_backend: local`, pointing to local Ollama (`http://127.0.0.1:11434`), `vlm_model: qwen3.5:9b`, and `embed_model: embeddinggemma-2:740m`.

### 3.2. Multi-Class COCO Tracking
- Configured YOLO11 inference for all 80 COCO classes (`detection_classes: [0..79]`).
- Confirmed tracks pass the detected `object_class` context into the VLM prompt, allowing the VLM to describe cars, bottles, chairs, laptops, and animals with class-specific attributes.
- Stored `object_class` in SQLite `track_events` and dynamically rendered in the UI results card.

### 3.3. Class-Based Query & Temporal Resolution Engine
Created [`runtime/streamcore/events/time_resolver.py`](../runtime/streamcore/events/time_resolver.py) (and alias `query_tools.py`) as a modular class **`TimeAndQueryResolver`**:
- **`resolve_camera(text)`**: Extracts camera numbers and validates against the installation's configured camera list (`CAM001`), preventing non-existent cameras (e.g. `Cam 57`) from breaking queries.
- **`resolve_calendar_date(text, ref_local)`**: Calculates exact calendar dates for weekdays (`on wednesday evening`), weekends, yesterday, and today.
- **`resolve_relative_time(text, ref_local, target_date)`**: Handles phrases like `just now` (last 25 mins), `earlier today`, `last X hours/minutes`.
- **`resolve_clock_range(text, target_date, padding_minutes)`**: Resolves explicit ranges and fuzzy prepositions (`around 3pm`, `after 4pm`, `before 11am`, `between 9:00AM to 11:00AM`) with configurable soft padding.
- **`resolve_named_period(text, target_date)`**: Resolves colloquial periods like `lunch time` (12:00–14:30), `morning` (06:00–12:00), `sunset` (17:45–19:15), `late night` (23:00–04:00).
- **`extract_visual_attributes(text)`**: Structured extractor for colors, garments, and actions (`using mobile`, `drinking`, `typing`, `holding`).
- **`clean_visual_query(text)`**: Strips camera, temporal, and filler words to present clean visual text to the vector embedder.
- **`parse_query(query, ref_utc)`**: Master pipeline coordinating all methods into a structured query payload.
- **`get_tool_schemas()`**: Exposes standard tool definitions for local LLM function calling.

### 3.4. Database & FAISS Vector Store Integration
- **`runtime/streamcore/events/event_db.py`**:
  - Added `get_events_by_ids(event_ids: list[str])` for chunked batch retrieval of full records from SQLite `track_events`.
  - Maintained `vector_id_map` for continuous row indexing in FAISS without JSON sidecar drift.
- **`runtime/streamcore/events/vector_store.py`**:
  - Updated `FaissVectorStore.search()` to batch-hydrate candidates from `events.db`.
  - Enforced camera ID and timestamp range filtering.
  - Ensured every returned result contains populated `snapshot_path`, `clip_path`, `description`, `object_class`, and `started_at_utc`.

### 3.5. Web Preview UI & API Updates
- **`runtime/streamcore/preview/preview_server.py`**:
  - Added `/api/status/search` and updated `/api/settings/gemini` to report local VLM and embedder connectivity.
  - Updated UI status pill to **`🟢 Local VLM Active (Qwen 3.5 9B + EmbeddingGemma)`** (or `🟡 Local CV Fallback` when offline).
  - Ensured search cards render the extracted object class, snapshot thumbnail, similarity percentage, VLM description, and playable MP4 clip with HTTP 206 Range support.

## 4. SQLite Database Schema Reference

Database path: `runtime/streamcore/output/events.db`

### Table 1: `track_events`
```sql
CREATE TABLE track_events (
    event_id          TEXT PRIMARY KEY,
    track_id          TEXT NOT NULL,
    track_session_id  TEXT NOT NULL,
    camera_id         TEXT NOT NULL,
    event_type        TEXT NOT NULL,
    object_class      TEXT NOT NULL,
    started_at_utc    TEXT NOT NULL,
    ended_at_utc      TEXT,
    duration_seconds  REAL,
    max_confidence    REAL,
    avg_confidence    REAL,
    description       TEXT,
    snapshot_path     TEXT,
    clip_path         TEXT,
    clip_recorded     BOOLEAN DEFAULT 0,
    metadata          TEXT,
    created_at        REAL NOT NULL,
    updated_at        REAL NOT NULL
);
```

### Table 2: `vector_id_map`
```sql
CREATE TABLE vector_id_map (
    faiss_row   INTEGER PRIMARY KEY,
    event_id    TEXT NOT NULL,
    created_at  REAL NOT NULL
);
```

### Indexes
```sql
CREATE UNIQUE INDEX idx_vidmap_event ON vector_id_map(event_id);
CREATE INDEX idx_camera_time         ON track_events(camera_id, started_at_utc);
CREATE INDEX idx_track               ON track_events(track_id, track_session_id);
CREATE INDEX idx_active              ON track_events(camera_id) WHERE ended_at_utc IS NULL;
CREATE INDEX idx_type                ON track_events(event_type);
```
